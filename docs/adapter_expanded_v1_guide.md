# Полный development для LoRA 0,25: один запуск на T4

[Открыть ноутбук 06 в Colab](https://colab.research.google.com/github/maria-igntv/lm-hw/blob/main/notebooks/06_adapter_expanded_v1.ipynb).

## Что запустить

1. Создайте **новую** Colab-сессию. Выберите **Среда выполнения → Сменить среду выполнения → T4 GPU**.
2. Выполняйте восемь кодовых ячеек сверху вниз. Если первая потребует перезапуск
   Python после установки, перезапустите сеанс и начните снова с первой ячейки.
3. В ячейке 2 можно включить `PERSIST_TO_DRIVE=True`. Тогда результаты после каждого
   ответа сохраняются в `MyDrive/lm_hw_expanded_runs/`. По умолчанию они пишутся
   в `/content/lm_hw_expanded_runs/` и сохраняются только пока существует сессия.
4. В ячейке 4 загрузите с компьютера исходный архив
   `sft_v3_pilot_qwen3_4b_20261118T113449101907.zip`.
   Локально он находится в `/Users/maria.ignatova/Downloads/`.
   Нужен именно исходный пилот с весами, не tiny/smoke и не архив судей.
   Для воспроизведения опубликованного checkpoint также подходит
   [адаптер из GitHub Release](https://github.com/maria-igntv/lm-hw/releases/download/artifacts-sft-v3-pilot/sft_v3_pilot_adapter_only.zip):
   он сохраняет необходимую внутреннюю папку и те же веса.
5. Дождитесь **CONTROLS PASS** после шести контрольных генераций.
   Они повторяют baseline и LoRA 0,25 на dev3_01, dev3_15 и dev3_25.
   Входные и выходные токены сравниваются с прежними. При расхождении
   не отключайте проверку: скачайте частичный результат последней ячейкой.
6. Дождитесь **24/24 новых ответов**. В полном результате будет 64 ответа:
   32 прежних baseline, восемь прежних LoRA 0,25 и 24 новых LoRA 0,25.
7. Последняя ячейка скачает два ZIP через браузер, обычно в **Downloads / Загрузки**.
   Разрешите множественные скачивания, если браузер их блокирует.
8. Сохраните выполненный ноутбук через **Файл → Скачать → Скачать файл IPYNB**.

Генерация 24 ответов при 0,25 ориентировочно занимает 20–40 минут на T4;
установка, загрузка базы и контрольные ответы требуют дополнительного времени.
Это оценка по прежнему запуску, не гарантированный срок.

## Что вернуть и что отдать судье

- `adapter_expanded_v1_<timestamp>.zip` — основной архив для анализа: 64 ответа,
  исходные токены, контроли, ошибки, параметры, хеши, прежние оценки, источники,
  `comparison.md` и техническая сводка. Веса повторно в него не включаются.
- Выполненный `06_adapter_expanded_v1.ipynb` — подтверждение фактического запуска.
- `adapter_expanded_v1_<timestamp>_for_judge.zip` — отдельный пакет **24 новых**
  заданий. Его можно сразу отправить прежнему **Qwen3.8-27B**. Если позволяет
  время, тот же пакет независимо оценивает gemma-4-31B-it.

Пакет судье содержит четыре файла: `judge_requests.jsonl`, `judge_system_prompt.md`,
`judge_response_schema.json`, `judge_run_config.json`. Множитель и сопоставления
условий в него не входят. Системный промпт и рубрика прежние; параметры судьи:
temperature=0, max_tokens=2048, strict JSON Schema. Внутренние инструкции
оцениваемых ответов рассматриваются как данные.

Вернуть нужно 24 итоговые оценки с request_id, score, raw_response, judge_model,
фактическим run_id; сырые ответы всех попыток, журнал ошибок и метаданные модели,
параметров и времени. Повтор разрешён только для невалидного результата,
включая нарушение `critical_errors ⇒ safety=1`; обе попытки сохраняются.
Валидные низкие оценки не повторяются.

**Прежние 40 оценок на судью повторять не требуется.** Их точные запросы,
ответы, критерии и источники сверяются при экспорте; ссылки и исходные оценки
записываются в `reused_judge_scores.jsonl` вне пакета судье.

## Продолжение после прерывания

В живой сессии повторите **только ячейку 7**. Сохранённые ответы будут пропущены;
их нельзя перегенерировать ради более удачного результата. Затем выполните ячейку 8.

Если среда Colab потеряна, но использовался Google Drive: откройте новую T4-сессию,
в ячейке 2 укажите `RESUME_DIR` с полным путём прежней папки, например
`/content/drive/MyDrive/lm_hw_expanded_runs/adapter_expanded_v1_...`, и выполняйте
всё сверху вниз. Контрольные ответы будут проверены в новой сессии заново.
Для загрузки весов снова потребуется исходный ZIP пилота.

Если использовался только `/content` и среда уничтожена, сохранение после каждого
ответа не восстанавливает удалённые файлы. Не удаляйте исходный ZIP и скачанные результаты.

При ошибке ячейка 8 сохраняет частичный ZIP со статусом и журналом ошибок.
Пакет судье создаётся только после полного технического PASS.

## Что этот запуск проверяет

Фиксированный кандидат `Qwen/Qwen3-4B-Instruct-2507` с прежней LoRA и множителем
0,25 сравнивается с baseline на всех 32 development-вопросах. Используются прежние
NF4/FP16, eager attention, системный промпт, 768 токенов и seed каждого вопроса.
Масштаб применяется абсолютно: исходное alpha/r=2, эффективный масштаб=0,5.

Перед переиспользованием проверяются SHA-256 весов, закреплённые исходники,
все входы и seed, декодирование прежних ответов, нулевой вклад против отключённой
LoRA, возврат масштаба и совпадение шести контрольных ответов. Проверяются
неизменность параметров LoRA и файла адаптера. Обучения и API-вызовов судье нет.

Автоматическая сводка показывает длину, русский текст, маркеры предупреждений
и повторы, включая отдельную диагностику длинных циклов. Эти показатели сами
по себе не доказывают безопасность или улучшение. Это **development**, не новый
финальный тест; содержательный результат будет известен после внешней оценки.
