# Диагностика силы адаптера без нового обучения

Ноутбук подготовлен в полученном пользователем комплекте продолжения
и перенесён в репозиторий без изменения кода. Его формат, синтаксис,
семь хешей исходных файлов и чистые функции проверены локально.
На маленькой Qwen3 на CPU проверены настоящий PEFT set_scale,
нулевой вклад, возврат масштаба, неизменность параметров и RNG.
Полный запуск Qwen3-4B NF4 на T4 ещё предстоит.

1. Откройте [ноутбук в Colab](https://colab.research.google.com/github/maria-igntv/lm-hw/blob/main/notebooks/05_adapter_strength_diagnostic_v1.ipynb).
2. Создайте новую сессию **T4 GPU**. Выполняйте семь кодовых ячеек
   по порядку. Версии закреплены, включая PyTorch 2.14.1+cu130.
   Если после установки требуется перезапуск Python, выполните его
   и начните снова с первой ячейки.
3. В третьей кодовой ячейке оставьте `ZIP_SOURCE='upload'`.
   При появлении выбора файла загрузите **исходный ZIP SFT-пилота**:
   `sft_v3_pilot_qwen3_4b_20261118T113449101907.zip`.
   Он содержит веса адаптера. Комплект lm_hw_continuation_package.zip
   содержит результаты судей и код, поэтому для загрузки весов нужен
   именно исходный архив пилота.
4. Для Google Drive выберите `ZIP_SOURCE='drive'` и укажите путь
   внутри подключённого Drive в `DRIVE_ZIP`.
5. Дождитесь проверки SHA-256, загрузки базы, начальных контролей,
   затем **32 sampling-ответов и 12 greedy-контролей**.
   Дополнительные шесть коротких эталонных контролей используются
   внутри технических проверок и записаны отдельно.
6. При успехе появится `TECHNICAL PASS`. Последняя ячейка создаст
   и скачает `adapter_strength_v1_<timestamp>.zip` через браузер.
7. Сохраните выполненный IPYNB через **Файл → Скачать → Скачать файл IPYNB**.
   Верните ZIP и IPYNB для содержательного разбора.

Множители 0 / 0,25 / 0,5 / 1 применяются абсолютно относительно
alpha/r=2. Исходные веса не изменяются, оптимизатора и обучения нет.
При нуле результат сравнивается с отключённым адаптером; при возврате
к единице проверяются logits и greedy-токены внутри одной сессии.
Каждая генерация сохраняет и восстанавливает Python/NumPy/CPU/CUDA RNG.

Основные sampling-ответы используют прежние 768 токенов, temperature=0.7,
top_p=0.8, top_k=20 и исходный seed вопроса из полного набора 32.
Greedy-контроли имеют лимит 64 токена и хранятся отдельно.
Восемь вопросов выбраны после ошибок, поэтому это диагностический
development, а не независимый тест.

Каждый ответ сохраняется сразу. После прерывания генерации повторите
шестую кодовую ячейку в текущей живой сессии. Последнюю ячейку
можно использовать для скачивания частичного результата после
создания каталога RUN_DIR. При ошибке сохраните также выполненный
ноутбук с выводом. После потери сессии начните новый запуск.

Неизменность весов, отсутствие циклов и технический PASS сами по себе
не подтверждают правильность действий. Содержание всех вариантов
проверяется после получения результата. Затем определяется дизайн
следующего обучения с LR=1e-5.
