# Запуск SFT v2

## Что подготовлено

Новый ноутбук находится в `notebooks/03_sft_train_v2.ipynb`.
Он обучает новый LoRA-адаптер от исходной Qwen2.5-3B-Instruct с
`learning_rate=5e-5` и одной эпохой. Мониторинг работает через TensorBoard,
ключ не требуется. Рабочие настройки точности из успешного прогона 03 сохранены.

Данные-кандидат находятся в `data/sft_v2/`. Все 650 исходных записей сохранены,
для 41 внесены содержательные правки по результатам аудита 48 примеров. Ещё 7
оставлены с оговорками. 602 записи сохраняют статус `not_reviewed`. Полной
экспертной проверки корпуса не было; успешный smoke-тест подтверждает работу кода.

В новом split 560 train и 90 validation. Во всех 8 категориях есть обучающие
и валидационные примеры. Назначенные группы сценариев не пересекаются между
частями, включая похожие сценарии из разных исходных категорий. Группировка
эвристическая, поэтому семантическую независимость каждого возможного перефразирования
она не гарантирует. Подробности находятся в manifest и group_assignments.

## 1. Откройте новый ноутбук

https://colab.research.google.com/github/maria-igntv/lm-hw/blob/main/notebooks/03_sft_train_v2.ipynb

Начните в новой сессии Colab. Выберите «Среда выполнения → Сменить среду
выполнения → T4 GPU». Код и данные скачиваются из GitHub. ZIP проекта не нужен.

## 2. Выполните smoke-тест

В первой кодовой ячейке уже стоит `SMOKE_TEST=True`.
Запускайте ячейки последовательно. Этот режим выполняет 5 шагов на 16 обучающих
и 8 валидационных примерах. Предварительные проверки формата и длины выполняются
для всех 650 записей.

Перед обучением проверьте вывод маскирования. В реально обучаемом тексте должны
быть ответы ассистента. Код проверяет отсутствие loss на всех токенах промпта
в 10 примерах и сохраняет эти проверки в файл.

Технический прогон также должен сохранить адаптер, график и логи. Результат
скачивается как `sft_v2_smoke.zip`. Его используйте только для проверки пайплайна.

При ошибке длины, маскирования или удаления примеров разберите её до полного
прогона. Не отключайте assert ради продолжения.

## 3. Выполните полный эксперимент

После успешной проверки запустите ноутбук в свежей среде с `SMOKE_TEST=False`.
Модель снова загружается от исходной базы. На одной T4 ожидается около 35 шагов
оптимизации для 560 примеров при эффективном batch 16. Время зависит от Colab.

Параметры версии v2 являются стартовой гипотезой. Мы одновременно меняем часть
данных, split, learning rate и число эпох. Результат покажет эффект комбинации;
вклад каждого изменения по отдельности такой эксперимент не определяет.

Validation loss v1 и v2 рассчитаны по разным наборам. Сравнивать абсолютные значения
между версиями как доказательство улучшения нельзя. Внутри v2 loss используется
для выбора чекпоинта; итоговое качество оценивается на одинаковых вопросах.

## 4. Скачайте результат

Последняя ячейка скачивает `sft_v2.zip`. Внутри должны быть:

- `adapter/` — новый адаптер и токенизатор;
- `run_metadata.json` — версии, параметры, размеры данных и результат обучения;
- `trainer_log_history.json` и `trainer_state.json` — числовые логи и лучший шаг;
- `training_args.json` — конфигурация Trainer;
- `dataset_manifest.json` — версия и хеши данных;
- `mask_audit.jsonl` — проверенные обучаемые части текста;
- `token_lengths.json` — длины всех 650 примеров;
- `loss_curve.png` и `tensorboard/` — график и логи мониторинга.

Также скачайте выполненный ноутбук через меню Colab «Файл → Скачать → IPYNB».
Сохраните оба файла до закрытия сессии.

## 5. Оцените новый адаптер

Откройте прежний `04_eval.ipynb` в новой сессии T4. Загрузите `sft_v2.zip`.
В архиве ровно одна папка с adapter_config.json, поэтому ячейка загрузки должна
найти её. В шаге с настройками задайте
`OUT_DIR = ROOT / 'results/eval_sft_v2'`.

Остальные условия сравнения сохраняются. Получите новые 100 ответов и скачайте
архив результатов. Для оценки смыслового качества используйте того же
Qwen3.8-27B и исходный протокол. Он вновь оценивает 100 ответов v2.
Исходные 100 оценок baseline уже сохранены. Их можно повторно использовать,
если версия судьи, рубрика и параметры совпадают; различия доступной версии
или условий нужно зафиксировать и при необходимости переоценить обе группы.

Экзаменационные вопросы не добавляйте в обучающую выборку. Поскольку их ответы
уже подробно изучались, это ограничение эксперимента следует указать в отчёте.

## Воспроизведение подготовки данных

Из корня репозитория выполните:

```bash
python3 script/prepare_sft_v2.py
python3 -m unittest checks.test_sft_v2 -v
```

Скрипт читает v1 raw-файлы, применяет записанные решения аудита, нормализует
system prompt, назначает группы и выполняет детерминированный split. Исходные
данные и результаты v1 сохраняются отдельными файлами.

## Что проверено до публикации

Проверены совпадение хешей при повторной сборке, покрытие категорий, отсутствие
пересечения назначенных групп и найденных близких пар между train и validation.
Все 650 примеров проверены реальным токенизатором Qwen2.5-3B: максимум 577
токенов, превышений 1024 нет.

Локально на Qwen2.5-0.5B без NF4 проверены подготовка данных, создание SFTTrainer,
маскирование, короткий обучающий прогон и сохранение адаптера. GPU-путь T4/NF4
в этой версии ещё не выполнен. Первым запуском в Colab должен быть smoke-тест.
