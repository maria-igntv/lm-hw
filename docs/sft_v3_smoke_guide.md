# Пункт 3: проверить обучение Qwen3-4B на T4

В сравнении двух базовых моделей оба судьи выбрали
`Qwen/Qwen3-4B-Instruct-2507` с бытовым системным промптом.
[Результаты сравнения](../results/model_screening_v3/judges/analysis.md).

Теперь нужно подтвердить, что на T4 корректно работает обучение LoRA.
LoRA — небольшие обучаемые матрицы, добавленные к замороженным весам модели.
В этом тесте выполняется всего один шаг обновления на четырёх простых
проверенных арифметических примерах. Он проверяет технический процесс;
измерять улучшение бытовых ответов будем после подготовки корпуса и SFT-пилота.

## Как запустить

1. Откройте [02_sft_v3_smoke в Google Colab](https://colab.research.google.com/github/maria-igntv/lm-hw/blob/main/notebooks/02_sft_v3_smoke.ipynb).
2. Выберите **Подключиться → Подключиться к размещённой среде выполнения**,
   затем **Среда выполнения → Сменить среду выполнения → T4 GPU**.
   Лучше использовать новую сессию, чтобы предыдущие модели не занимали память.
3. При желании сохраните копию ноутбука на Google Drive через меню «Файл».
4. Выполняйте ячейки сверху вниз. Первую ячейку нужно дождаться: она
   клонирует репозиторий и устанавливает закреплённые версии библиотек.
   Модель, промпт и настройки уже выбраны. Ничего загружать вручную не нужно.
5. Если после установки явно запрошен перезапуск Python, выполните его
   и снова начните с первой ячейки. Сохранённые файлы `/content` сохраняются
   при перезапуске Python, но могут исчезнуть при удалении всей сессии.
6. Дождитесь вывода **`SMOKE PASS`** в ячейке сохранения адаптера.
7. Запустите последнюю ячейку: браузер скачает ZIP на ваш компьютер.
   Обычное место — папка «Загрузки»; если браузер спрашивает место, выберите его.
8. Сохраните выполненный ноутбук: **Файл → Скачать → Скачать файл IPYNB**.
   Для разбора результата нужны этот IPYNB и ZIP.

Внутри Colab результаты находятся в
`/content/lm-hw-v3/results/sft_v3_smoke/<run_id>/`.
Архив получает имя `sft_v3_smoke_<run_id>.zip` и сначала создаётся в `/content`.
Команда `files.download(...)` переносит его из Colab через браузер.
Загрузка в репозиторий GitHub при этом автоматически не выполняется.

## Какие проверки выполняет ноутбук

| Проверка | Зачем она нужна | Что ожидаем |
| --- | --- | --- |
| Закреплённые ревизия модели и промпт | Связать обучение с выбранным baseline | Совпадение с selection.json |
| 4-bit NF4, FP16, eager, GPU | Проверить реальную загрузку на T4 | Веса на GPU, без CPU-offload |
| Маски loss | Учить ответ ассистента и окончание сообщения | System, user и padding исключены меткой -100; EOS включён |
| Свежий адаптер | Убедиться, что подключение само не меняет результат | Нулевые матрицы B; logits с адаптером и без него совпадают |
| Четыре backward и один AdamW | Подтвердить работоспособность обучения | Конечные loss/градиенты, B после шага изменяются |
| Пик памяти | Измерить память при длине 768 и batch=1 | Шаг завершается на T4 |
| Safetensors | Проверить сохранение реальных весов | Непустой файл, все тензоры конечны |
| Выгрузка и загрузка адаптера | Убедиться, что файл воспроизводит адаптер | Совпадают контрольные logits и greedy-токены |

`logits` — численные оценки вариантов следующего токена. Их сравнение
проверяет подключение и загрузку точнее, чем сходство двух текстов.
Greedy выбирает самый вероятный токен, поэтому здесь можно сравнить сами
последовательности без случайного sampling.

Подготовка модели к k-bit-обучению переводит часть весов в float32 и включает
gradient checkpointing. Её влияние на logits записывается отдельно.
Для нулевого вклада LoRA сравнивается одна и та же уже подготовленная модель
с включённым и отключённым адаптером.

Настройки: LoRA r=16, alpha=32, dropout=0 на семи проекциях;
LR=5e-5; batch=1; accumulation=4; один шаг AdamW;
дополнение каждого входа справа до 768 токенов. Арифметические примеры
короче 768, но дополнение позволяет проверить память на выбранной длине.
Следующее полноценное обучение потребует отдельного теста качества и
проверки длин уже настоящих обучающих примеров.

## Что будет в ZIP

- `checks.json` — общий PASS при успешном завершении.
- `run_metadata.json`, `pip_freeze.txt`, `reproduction/` — модель,
  параметры, версии, GPU, commit и копии файлов для воспроизведения.
- `mask_audit.jsonl`, `training_controls.jsonl` — обучаемые токены и четыре примера.
- `fresh_adapter_check.json` — проверка нулевого вклада LoRA.
- `training_losses.jsonl`, `training_summary.json` — loss, градиенты,
  время и память одного шага.
- `save_reload_check.json` — сравнение после повторной загрузки.
- `adapter/` — safetensors, конфигурация адаптера и токенизатор.
- `errors.jsonl` — журнал ошибок; при успехе пустой.

Этот контрольный адаптер нужен для проверки процесса. Для итоговой модели
потребуется новое обучение с исходной базовой модели на проверенном корпусе.

## Если возникла ошибка

Если папка результата уже создана, выполните последнюю ячейку скачивания
даже после ошибки. Сохраните ZIP и выполненный IPYNB. Ошибка и промежуточные
проверки помогут понять, на каком этапе возникла проблема.

Если ошибка случилась при установке пакетов или до создания `OUT_DIR`,
сохраните IPYNB с выводом: ZIP ещё может отсутствовать.
Если браузер заблокировал скачивание, разрешите его и повторите последнюю ячейку.

Не повторяйте ячейку оптимизатора в том же запуске: это добавит ещё один шаг.
При повторе после успешного шага ноутбук останавливает эту ячейку.
После частично выполненного шага с ошибкой сохраните логи и начните новый
полный запуск в новой сессии, чтобы исходное состояние было известно.
