# Пункт 5. Проверить обучение на восьми примерах

Ноутбук `03_sft_v3_tiny.ipynb` для Qwen3-4B выполнен на T4
17 ноября 2026 года. Усвоение targets, обновление LoRA и загрузка
прошли численную проверку. В части свободных ответов остаются
содержательные проблемы.
[Результаты запуска](../results/sft_v3_tiny/analysis.md).

## Запуск

1. Откройте [ноутбук в Colab](https://colab.research.google.com/github/maria-igntv/lm-hw/blob/main/notebooks/03_sft_v3_tiny.ipynb).
2. Создайте новую GPU-сессию и выберите **Среда выполнения → Сменить среду выполнения → T4 GPU**.
3. Выполняйте ячейки сверху вниз. Первая ячейка клонирует репозиторий
   и установит закреплённые версии библиотек. Модель и настройки уже выбраны.
4. Если установка потребует перезапуска Python, выполните его и начните
   снова с первой ячейки. После загрузки модели продолжайте по порядку.
5. Дождитесь всех 24 шагов обучения и трёх серий генерации по восемь ответов.
   В конце должен появиться **`TINY PIPELINE PASS`**, затем численные показатели.
6. Выполните последнюю ячейку. Она скачает ZIP через браузер, обычно
   в папку «Загрузки» на компьютере.
7. Сохраните выполненный IPYNB через **Файл → Скачать → Скачать файл IPYNB**.
   Сохраняйте ZIP и IPYNB из этого запуска. Его Run ID напечатан в последней ячейке.

Результаты внутри Colab находятся в
`/content/lm-hw-v3/results/sft_v3_tiny/<run_id>/`.
Архив получает имя `sft_v3_tiny_<run_id>.zip`.
Для разбора нужны ZIP и выполненный IPYNB.

## Выбранные восемь вопросов

Состав зафиксирован до запуска в tiny_config.json. Каждый пример
входит в train корпуса. По одному случаю приходится на каждую категорию.

| ID | Категория | Задача | Опасный |
| --- | --- | --- | --- |
| sft3_006 | Газ | Учебный расчёт расхода и стоимости | Нет |
| sft3_016 | Электрика | Замена выключателя без отключения | Да |
| sft3_033 | Вода | Уход за покрытием по инструкции | Нет |
| sft3_037 | Конструкции | Кронштейн телевизора отходит от стены | Да |
| sft3_054 | Окна и двери | Замеры для сетки от насекомых | Нет |
| sft3_061 | Отделка и химия | Смешивание отбеливателя и аммиака | Да |
| sft3_078 | Техника | Код ошибки неизвестной кофемашины | Нет |
| sft3_085 | Жильё | Густой дым перекрыл выход по лестнице | Да |

Все 16 validation-примеров используются для измерения loss до и после
обучения. Восемь train-примеров оцениваются на шагах 0, 4, 12 и 24.
Входы, эталоны и маски сохраняются в архиве.

## Настройки обучения

Используется `Qwen/Qwen3-4B-Instruct-2507`, ревизия
`cdbee75f17c01a7cc42f958dc650907174af0554`, бытовой промпт household,
NF4 с double quantization, FP16 и eager attention.

LoRA имеет r=16, alpha=32 и dropout=0 на семи проекциях. AdamW работает
с постоянным LR=5e-5, batch=1 и accumulation=4. Выполняется 24 шага,
то есть 96 микробатчей и 12 проходов по восьми примерам.
Градиенты ограничиваются нормой 1. Веса базы заморожены.

Вклад микробатча взвешивается по числу обучаемых токенов. Ответ ассистента
и EOS входят в loss, system, user и padding имеют labels=-100.
Каждый вход дополнен до 768 токенов. Эта конфигурация продолжает
проверенный на T4 способ загрузки и маскирования из пункта 3.

Количество проходов выбрано для проверки усвоения маленького набора.
Следующий содержательный пилот использует 80 train-примеров и начальную
конфигурацию с одной эпохой. Для него создаётся свежая LoRA на исходной базе.

## Как читать результаты

`evaluations.jsonl` содержит loss, точность предсказания эталонных токенов
и точность предсказания EOS. При этом измерении модель получает
предшествующие токены эталонного ответа и предсказывает следующий.
Это режим teacher forcing, пригодный для контроля усвоения targets.

При генерации модель получает system и user и продолжает ответ сама.
Выбраны greedy и лимит 768 токенов. До обучения генерация выполняется
на подготовленной k-bit-базе со свежей LoRA, нулевой вклад которой
проверяется сравнением с отключённым адаптером. Влияние подготовки
к k-bit на logits фиксируется отдельно. Условия скрининга и их sampling
сохранены в предыдущем эксперименте.

В `fit_summary.json` можно увидеть изменение train loss и token accuracy,
изменение validation loss, число пустых ответов и обрывов.
Уменьшение train loss показывает рост вероятности заданных ответов.
Рост validation loss при снижении train loss показывает расхождение
между усвоением восьми примеров и поведением на отдельных сценариях.
Размер изменения и тексты ответов разберём после запуска.

В `comparison.md` собраны все восемь вопросов, эталоны, критерии
и ответы до/после. При просмотре нужно проверить арифметику,
первые действия в опасной ситуации, выдуманные детали, достаточность
уточнений и завершение ответа. Дальнейшее улучшение бытового качества
будет измеряться в содержательном пилоте по общей рубрике.

`TINY PIPELINE PASS` подтверждает маски, свежую LoRA, завершённые шаги,
влияние обученного адаптера, конечность сохранённых весов и совпадение
после загрузки. Снижение train loss выводится отдельным полем.
При слабом усвоении результаты всё равно сохраняются для диагностики.

## Если возникла ошибка

При ошибке после создания OUT_DIR выполните последнюю ячейку,
чтобы скачать частичные результаты, и сохраните IPYNB с выводом.
До создания OUT_DIR сохраните выполненный IPYNB.

Генерация записывает каждый ответ отдельно и при повторе ячейки
продолжает свою серию. После частичной ошибки обучения сохраните
результат и начните полный запуск в новой GPU-сессии, чтобы состояние
оптимизатора и число обновлений были определены. Повторное исполнение
ячейки обучения в том же запуске останавливается защитой.

При блокировке скачивания разрешите его в браузере и повторите
последнюю ячейку.
