# Оценка промежуточных масштабов LoRA: 16 новых ответов

[for_judge.zip](for_judge.zip) содержит по восемь ответов
при множителях 0,25 и 0,5. Вопросы, тексты, источники и рубрика
зафиксированы; запросы перемешаны и скрывают масштаб модели.
Получены и проверены по 16 оценок Qwen и Gemma. Был один разрешённый
повтор невалидного ответа Qwen, всего 33 вызова и 32 итоговые новые оценки.
[Разбор четырёх масштабов](../../results/adapter_strength_v1/judges/analysis.md).
Статус package_manifest.json фиксирует момент подготовки исходного пакета.

В архиве четыре файла: judge_requests.jsonl, judge_system_prompt.md,
judge_response_schema.json, judge_run_config.json.
Передавайте system_prompt как system, user_prompt как user,
сохраняйте request_id. Параметры прежние: Qwen3.8-27B,
temperature=0, max_tokens=2048, ответ по JSON Schema.
При возможности тот же пакет независимо оцените gemma-4-31B-it.

При повторении нужно вернуть по 16 валидных JSON-ответов от каждого использованного
судьи, сырые ответы, ошибки и фактические метаданные запуска.
Текст ответа ассистента и критерии не изменяйте.
judge_mapping.json хранится отдельно и в архив не включён.

Масштабы 0 и 1 дают токен в токен те же ответы, что baseline/SFT
предыдущего пилота. Их прежние судейские оценки доступны
в results/sft_v3_pilot/judges/. Проверенные ссылки request_id
сохранены в endpoint_score_reuse.json. Так можно сопоставить
все четыре масштаба, добавив только 16 новых оценок каждому судье.

Восемь случаев выбраны после обнаружения ошибок: это диагностический
development. Новые оценки не являются результатом свежего финального теста.
[Разбор диагностики](../../results/adapter_strength_v1/analysis.md).
